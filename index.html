One file describes the whole app.

Frame is a small language for declaring an app's data, actions, screens, limits, recovery and repair in one place. The compiler turns it into a native Rust backend and a browser UI, and checks that what you declared is what runs.

The reference app, annotated

This is examples/fieldwork/fieldwork.frame, exactly as it ships. Two users create, list and complete their own tasks. The marked lines are the ones the compiler and runtime hold you to.

frame "0.1";app fieldwork {  targets = [web];  identity development {    mode = local_dev;  }
  entity Task {    owner_field = owner;    // id and revision are supplied by the runtime.    field title {      type = Text;      min_length = 1;      max_length = 200;    }    field owner {      type = UUID;    }    field completed {      type = Bool;      default = false;    }  }

Every task belongs to a user. Generated queries are scoped to the signed-in owner, so one user can never read or change another user's tasks.

  action create_task {    kind = insert;    entity = Task;    access = signed_in;    input title {      type = Text;      min_length = 1;      max_length = 200;    }    set = {      title: @input.title,      owner: @actor.id,    };  }

The owner comes from the session, never from the request body. Inputs are checked against their declared bounds before any SQL runs.

  action list_tasks {    kind = list;    entity = Task;    access = signed_in;  }
  action complete_task {    kind = update;    entity = Task;    access = signed_in;    input id {      type = UUID;    }    input revision {      type = Int;    }    id = @input.id;    expected_revision = @input.revision;    set = { completed: true };  }

Updates check the record's revision. A stale write gets a conflict instead of silently overwriting someone else's change.

  screen tasks {    route = "/";    title = "My tasks";    query = list_tasks;    form add_task {      submit = create_task;      input title {        label = "Task title";        placeholder = "What needs doing?";      }    }    list task_list {      source = @query.items;      fields = [title, completed];      button complete {        label = "Mark complete";        action = complete_task;        arguments = {          id: @item.id,          revision: @item.revision,        };      }    }  }

Screens are built from native browser controls and bound to actions. A button can only call what its action allows.

  runtime local {    bind = "127.0.0.1";    port = 7331;    database = ".frame/app.db";    request_limit_bytes = 65536;    request_timeout_ms = 5000;  }

Limits live in the source. The runtime enforces body size, timeouts and per-user rate limits on every request.

  recovery backend_process {    target = backend;    max_restarts = 3;    window_seconds = 60;    backoff_ms = [100, 500, 2000];    after_exhaustion = stop;  }

A separate supervisor restarts the backend within this budget. When the budget runs out, it stops and tells you instead of looping.

  repair local_candidate {    mode = isolated;    max_attempts = 2;    editable_actions = [complete_task];    automatic_release = false;  }

When a protected test fails, Frame proposes a fix and validates it in a sandbox. It may edit only these actions, and nothing ships until you apply it.

What frame build writes

Everything the compiler produces lands in .frame/ next to your source. The IR and graph are deterministic and hashed, so the same source always gives the same output. Agents read a bounded context for the one node they are changing, not the whole project.

.frame/
├── ir.json             typed IR with semantic and source hashes
├── graph.json          every node and the edges between them
├── generated/app/      Rust backend: Axum and SQLx on SQLite
├── generated/web/      browser UI built from native controls
├── generated/runtime/  the runtime the backend links against
├── build/              the compiled backend
└── context/<node>/     bounded context for changing one node

Install

Frame compiles apps with Cargo, so install Rust with rustup first. Generated apps pin their own Rust version, and rustup fetches it on the first build.

macOS, Apple silicon

curl -fsSL https://github.com/Alibek10599/frame/releases/latest/download/frame-aarch64-apple-darwin.tar.gz | tar -xz
sudo install frame-aarch64-apple-darwin/frame /usr/local/bin/frame

All releases

Your first app

frame init hello
cd hello
frame dev

frame dev builds the app, starts it under the supervisor, and prints a one-time link that signs you in as a local development user. The first build compiles the backend's dependencies and takes about a minute.

What 0.1 does not do yet

0.1 runs on your own machine. Mobile targets, production sign-in, PostgreSQL, migrations, workflows and deploys come in later releases. Declaring any of them today fails with a diagnostic instead of being quietly ignored.

Sandboxed repair needs macOS. On Linux, repair stops after static validation and reports that no sandbox is available.
